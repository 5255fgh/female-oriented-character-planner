# Female-oriented Character Planner

女性向互动角色策划与猫箱输入包生成器。项目把一句话灵感整理为经过契约校验的角色、世界、开放故事和平台输入包；所有项目数据保存在本地浏览器中。它不是聊天客户端，不会自动登录、操作或发布到猫箱。

## 当前状态

v0.2.0 已完成核心模块、正式 UI 与跨模块接线，并通过完整 Mock 端到端、浏览器流程、测试和生产构建验证。启动开发服务器后可直接从首页创建角色、创建开放故事、恢复本地项目或导入 JSON；默认使用不需要 API Key 的 Mock 演示模式。

核心流程有两种角色入口：

- 默认入口从 `CreativeSeed` 开始，最多追问 3 个高影响问题，然后生成一份 `CreativeBrief` 和一个完整角色。
- 探索入口保留正好 3 个差异化方向，选择后扩展为完整角色。

角色生成后可以继续创建 `WorldBible` 与开放式 `StoryDraft`，执行快速 3 场景或完整 8 场景评估，按字段确认修改并撤销，再转换为猫箱输入包。

## 已实现的核心能力

### 一句话角色

- 严格校验非空的 `{ text }` 创作种子。
- 信息不足时最多返回 3 个追问，每题提供 3—5 个选项和一个安全推荐值。
- 默认只生成一个角色，不暗中创建三个候选。
- 兼容三方向生成模式；三个候选仍须在情绪回报、关系机制和冲突来源上有实质差异。
- 角色 ID 与时间戳由本地代码生成，模型结果使用前通过运行时契约校验。

### 开放故事

- `WorldBible` 只保留当前角色或故事需要的规则、地点、势力、既定事实和禁止事实。
- `StoryDraft` 固定包含正好 8 个关键节点，并限制开放分支、伏笔和状态说明数量。
- 故事产物是可继续互动的结构草稿，不是自动扩写的几十章小说。

### 评估与高级编辑

- 确定性规则检查将合同错误标为阻断问题，将有限启发式观察标为提醒。
- 快速测试固定 3 个边界场景；完整测试固定 8 个场景。
- 字段修改先返回提案，确认后只改变目标字段；不会用一次重生成覆盖完整角色。
- 文本、数组和 JSON Diff 可在确认前检查；撤销恢复最近一次字段值。
- 修改历史最多保留 20 条。角色变化会失效过期的故事、评估和平台包，但保留仍有效的世界设定。

### 保存、自动保存与导入导出

- `ProjectDocument` 可以在只有 seed、已有角色、已有故事或完整阶段保存。
- 自动保存按项目防抖并串行写入；`flush()` 可在切换项目或离开页面前立即提交最后版本。
- 项目、显式版本和恢复版本保存在当前站点来源的 IndexedDB 中。
- JSON 使用 schema v2 信封，可导入旧裸 `CharacterProject`、v1 信封和 v2 信封。
- Markdown 导出用于人工阅读与归档；JSON 才是可重新导入的结构化备份。

这些能力已经接入正式 UI。普通修改自动保存；首次完整生成、确认 AI 字段修改和“立即保存版本”会留下可恢复快照。

### 猫箱输入包

核心适配器支持五种输出包：

- `editor_character`：编辑器角色字段。
- `free_character`：自由创建角色。
- `dead_rival`：亡者劲敌。
- `image_shape`：捏形象。
- `editor_open_story`：编辑器开放故事。

旧 `open_story` 只用于历史数据兼容，新项目不得生成该禁用入口。已知长度、枚举和验证状态见 [猫箱规则文档](docs/MAOXIANG_RULES.md)。未知上限保持 `null`，不会被替换成猜测值。

## 启动与使用

```sh
npm ci
npm run dev
```

打开终端显示的本地地址后：

- “创建角色”默认从一句话直接生成单个角色；需要比较方向时可选择“探索 3 个方向”。
- “创建开放故事”会生成共享世界、开放故事和正好 8 个剧情节点。
- “打开已有项目”读取当前浏览器来源中的 IndexedDB 草稿；刷新页面后也可恢复。
- “导入 JSON”接受旧裸项目、schema v1 与 schema v2，并在校验和迁移后创建新的本地项目。

结果页可以运行完整 8 场景测试、修改并确认单个角色字段、撤销最近修改、复制有效猫箱字段，以及导出 JSON 或 Markdown。生成和模型请求均可取消；取消后的迟到响应不会覆盖项目。

## Mock 模式与模型配置

稳定 Mock 覆盖 seed、角色、世界、故事、评估、平台包、保存和导入导出链路，不需要 API Key，适合开发和验收。

页面右上角可在“Mock 演示”和“真实 API”之间切换。真实模型使用 OpenAI Chat Completions 兼容接口；复制示例环境文件：

```powershell
Copy-Item .env.example .env.local
```

然后只在本机的 `.env.local` 中配置：

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的本地密钥
VITE_LLM_MODEL=deepseek-v4-flash
```

`LLM_API_KEY` 只由本地 Vite 代理读取并注入请求，不进入浏览器 bundle、Git、IndexedDB 或 localStorage。`VITE_LLM_MODEL` 只保存非敏感模型名。

## 开发与验证

环境要求：Node.js `20.19+` 或 `22.12+`，以及 npm。

```sh
npm ci
npm run dev
```

局域网调试可使用 `npm run dev:lan`；它会监听 `0.0.0.0`，只应在可信网络中运行。

提交前运行完整验证：

```sh
npm test
npm run smoke
npm run build
```

`npm test` 使用 Node 内置测试运行器并串行执行，以避免多个 Vite SSR fixture 争用端口。CI 会在 Node 20 和 Node 22 上重复执行安装、测试、smoke 和构建。

## 本地数据边界

项目只保存在当前浏览器和当前站点来源。更换浏览器、域名、端口或清理站点数据后，原数据可能不可见。重要项目应同时导出 JSON 和 Markdown 到受控备份位置。

本项目明确不实现：

- 自动登录猫箱或代替用户操作网页。
- 自动发布、批量创建或养号。
- 云同步、用户账号或把 API Key 存入前端。
- 多 Agent 生成或无限重试。
