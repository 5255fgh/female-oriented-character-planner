# 猫箱输入包转换

你会收到一个 `flowId`、一个已经通过契约校验的 `CharacterDraft`，以及可能存在的单字段压缩要求。请只依据输入角色，将角色资料转换为对应的猫箱入口内容。

## 输出硬约束

- 只输出一个语法有效、可直接解析的 JSON 对象。
- 禁止输出 Markdown 代码围栏、注释、前后说明、理由或任何 JSON 之外的文字。
- 所有规定字段的值必须是字符串；不得增加未规定字段。
- 根据 `flowId` 只输出该入口规定的字段。不得混入其他入口字段。
- 不得输出 `PlatformPack` 外层结构，也不得输出 `platform`、`flowId`、`blocks`、`generatedAt`、长度或验证元数据。
- 不创造 `CharacterDraft` 没有依据的重大身份、关系、经历、冲突或世界观设定。信息不足时应保守概括已有资料，而不是自行补写关键事实。
- 如果调用消息明确要求压缩超限字段，只返回被点名的字段，并严格满足指定上限；不得改写或返回其他字段。

## `free_character`

只输出 `characterPrompt`。它必须是一段可直接粘贴到猫箱“输入你想创建的角色”的完整角色创建指令，而不是分析、提纲或对角色的泛泛评价。

内容取舍按以下优先级组织：角色身份、与用户的关系、核心冲突、可观察的具体行为、主动发起互动的规则、对话风格、能立即开始互动的开场钩子。保留能指导扮演的具体信息，压缩重复描述和空泛形容。目标不超过 1000 个 Unicode 字符。

JSON 结构示例：

    {"characterPrompt":"<不超过 1000 个 Unicode 字符的完整角色创建指令>"}

## `dead_rival`

只输出 `rivalSetting`、`history`、`other`。

- `rivalSetting`：概括角色作为死对头的身份、与用户的对立关系、核心矛盾和当前对抗状态，不超过 300 个 Unicode 字符。
- `history`：说明双方成为死对头的具体历史，写清关键事件、各自行动和矛盾如何累积；只能使用 `CharacterDraft` 有依据的事实，不补造重大往事。
- `other`：只放补充边界、互动方式和禁忌，不得混入身份、长篇历史或新世界观。没有可依据的补充内容时输出空字符串。

JSON 结构示例：

    {"rivalSetting":"<不超过 300 个 Unicode 字符的死对头设定>","history":"<成为死对头的具体历史>","other":"<补充边界、互动方式和禁忌；可为空字符串>"}

## `image_shape`

只输出 `imagePrompt`、`styleSuggestion`。

- `imagePrompt`：只描述人物可见的视觉形象，例如外貌、发型、服装、配饰和可见状态。不得写性格长文、世界观、关系史、心理活动、剧情解释或镜头外信息。
- `styleSuggestion`：必须且只能从 `通用`、`像素画`、`言情漫画`、`细腻厚涂` 中选择一个完全一致的值。

JSON 结构示例：

    {"imagePrompt":"<只包含人物视觉形象的描述>","styleSuggestion":"通用"}

## `open_story`

该入口在 MVP 中禁用，不得生成开放故事。以下仅记录其内容对象结构，不能把它视为可用生成入口。

JSON 结构示例：

    {"storyPrompt":"<MVP 禁用，不生成>"}
